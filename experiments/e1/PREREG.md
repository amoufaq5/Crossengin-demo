# E1 pre-registration: which learning mechanisms change what the chat says?

**Status.** This file was registered before any ablation arm was run on
`inputs/replay_v1.tsv`. It is part of the commit that adds the harness (B4).
The study run (B7) uses that commit's inputs and scoring unchanged. Any later
change is listed under "Deviations" in the results' `REPORT.md`.

## 1. Question

The audit (§8, finding F-03) found that most of CrossEngin's learning
mechanisms are called on the chat path but may not change any reply. E1 asks,
for each mechanism:

1. Does switching it off change what the chat says?
2. Does it make the chat more or less correct on a fixed, scored replay?

## 2. Arms

Every arm runs the same chat binary. The arms differ only in environment flags,
which are listed in `arms.tsv` and described in `docs/EXPERIMENT_FLAGS.md`.

| Arm | Flags | Compared with |
|---|---|---|
| full | none | (reference) |
| abl_substrate | `CE_ABL_SUBSTRATE=1` | full |
| abl_ff | `CE_ABL_FF=1` | full |
| abl_pc | `CE_ABL_PC=1` | full |
| abl_cache | `CE_ABL_CACHE=1` | full |
| abl_ia | `CE_ABL_IA=1` | full |
| abl_synw | `CE_ABL_SYNW=1` | full |
| abl_beta | `CE_ABL_BETA=1` | full |
| abl_all | all seven ablations | full |
| hebb | `CE_HEBB=1` | full |
| hebb_nocache | `CE_HEBB=1 CE_ABL_CACHE=1` | abl_cache |

That gives 10 comparisons.

## 3. Inputs

`inputs/replay_v1.tsv` holds 262 lines: 200 scored items, 25 unscored probe
items and 37 feedback lines. They are grouped into episodes, and the episodes
into six blocks. The blocks always run in the order R, P, C, U, F, H.

| Block | Scored | What it probes |
|---|---|---|
| R: recall | 40 | Seed concepts, asked singly, twice in a row, or in related pairs (exercise/diet, question/ask, infection/symptom, need/hello) where the moment cache can return the other item's reply. |
| P: paraphrase | 30 | Rewordings that should reach the same reasoning chain as a canonical concept. |
| C: category | 40 | Arithmetic, greetings, thanks and farewells, social and personal replies, refusals, self-description, NL-grammar research, procedural, financial, debatable, yes/no. |
| U: unknown | 25 | Words and procedures the seed does not know. A first sight should give an honest gap that names the word. A second sight of a learned stub should give the "say more" reply. |
| F: feedback | 25 | A probe, then `/bad`, `/bad /bad`, `/good /good` or `/correct …`, then a scored follow-up. The follow-up is either the same question again (the reply should change), or a yes/no question on the reinforced or weakened operator (the hedge should follow the feedback). |
| H: held-out retest | 40 | Earlier items asked again at the end of the session, after all feedback. Some check stability; others check whether the learned changes persist. |

**Permutations.** `inputs/perms_v1.tsv` holds five permutations, generated by
`e1.py perms` with seeds 1–5. Each one shuffles the episodes within every
block; the order of lines inside an episode is fixed. Every arm runs all five
permutations.

**Run conditions.** Each (arm, permutation) pair runs in its own chat process
with a fresh private run dir (mode 0700). The process gets an environment built
from scratch: `HOME`, `CE_RUN_DIR`, `CE_EXP_TRACE=1`,
`CE_CAPS_CONF=inputs/caps_e1.conf` (denies every capability that could prompt
or reach the network), plus the arm's flags. An inert marker line
(`/__e1_<id>`) before each item makes the replies line up with the items.

## 4. Outcome

**Per-item correctness.** Each item's gold is in `inputs/gold_v1.tsv`. The spec
kinds:

| Kind | Correct when |
|---|---|
| `about=W` | The reasoning chain in the reply begins or ends at concept W. |
| `ops=CSV` | The EXP trace's operator ids equal CSV. This is the paraphrase check: the same chain as the canonical item. |
| `line=TEXT` | The `agent>` line equals TEXT. |
| `prefix=TEXT` | The `agent>` line starts with TEXT. |
| `differs=ID` | The `agent>` line differs from item ID's line in the same run, i.e. the reply changed after feedback. |
| `nl=1` | The NL grammar answered. |

**How the gold was written.** The semantic kinds (`about`, `ops`, `differs`
and the hedge prefixes `yes [from seed]` / `tentatively, yes`) follow the rules
above. They were not tuned to the system's output. Exact reply texts (`line=`,
and the other `prefix=` values) were transcribed from the chat's replies.

**Reference check.** `e1.py refcheck` runs every episode alone in the full arm.
At registration, 21 of 200 scored items fail their gold there. All of them are
behaviours this study is meant to measure:
- moment-cache collisions and replays after feedback: R04b–R12b, F01q, F02q, F04q, F05q, F25q;
- one semantic miss: R22 "pain";
- late-session changes seen in the file-order run: H03, H04, H06, H07, H25, H39.

Before registration, two yes/no items (F20 and F23) were replaced, because the
chat cannot parse them in any context ("i don't have a model of 'lead'").

**Arm-level score.** An item counts as correct for an arm if it is correct in at
least 3 of the 5 permutations.

## 5. Analysis

**Primary.** For each of the 10 comparisons, an exact two-sided McNemar test is
run over the 200 items:
- b = items correct in the comparator but not in the arm;
- c = items correct in the arm but not in the comparator;
- p = min(1, 2·Σ_{i≤min(b,c)} C(b+c, i) / 2^(b+c)).

The 10 p-values are Holm-adjusted, and a comparison is significant if its
adjusted p < 0.05.

**Secondary (descriptive, not tested).**
- `items_text_differs`: the number of scored items whose whole reply text (EXP
  lines removed) differs from the comparator's in at least one permutation.
  This measures behavioural change without any judgement of correctness.
- Pooled correctness per block (`blocks.tsv`), over item × permutation.

**Determinism gate.** The full arm is run twice on every permutation. If any
pair differs by a single byte, the study stops before scoring.

## 6. Hypotheses and predictions

- **H1: the moment cache costs correctness.** abl_cache is significantly better
  than full (c > b). The predicted gains are on related-pair, unknown, feedback
  re-ask and late-retest items, where full returns a cached reply that belongs
  to another input or was rejected by feedback.
- **H2: three mechanisms change nothing a user can see.** For abl_substrate,
  abl_pc and abl_ff, `items_text_differs` = 0 and b = c = 0. A single
  differing item refutes H2 for that arm.
- **H3: operator confidence (BETA) carries the hedge.** abl_beta is
  significantly worse than full (b > c). The losses should come from the yes/no
  items after feedback (F06–F24, H38, H39). abl_synw and abl_ia are predicted
  not to differ significantly from full: SYNW's compiled shortcuts are not
  expected to win a chain choice, and IA touches only F11 and H40.
- **H4: everything off.** No direction is predicted for abl_all vs full. It
  should gain where the cache hurts and lose where BETA helps. The result is
  reported either way.
- **H5: the B3 Hebbian step.** hebb vs full and hebb_nocache vs abl_cache are
  predicted not to differ significantly; Hebb changes the chain choice mainly
  at the fever fork.
  - **Decision rule:** `CE_HEBB` becomes on by default only if hebb_nocache vs
    abl_cache is significant with c > b, **and** no block's pooled
    correctness drops.

## 7. Known threats

- Items within one session are not independent: feedback in one episode can
  move operators that a later item uses. Permuting episodes and taking a
  majority over five permutations spreads that effect evenly across arms. It
  does not remove it.
- The gold encodes judgements: a reply about a different concept is wrong, a
  reply should change after `/bad`, and the hedge should follow the feedback.
  Other judgements would score differently. `items_text_differs` is reported
  for that reason.
- The seed knowledge is small (42 operators). Results describe this seed only.
- Disclosure: exploratory runs on ad-hoc scripts, which were not this replay,
  informed the item design. These are the cache collisions, the BETA/SYNW
  masking, and the observation that SUBSTRATE, PC and FF never changed a reply
  in those runs. Before registration, only the full arm ran on
  `replay_v1.tsv`: `refcheck`, and a two-permutation harness check with the
  determinism gate.

## 8. Outputs

`e1.py run` writes the following to its output directory:
- `manifest.json`: SHA-256 of the binary and of every input file;
- `raw/<arm>/p<k>.out`;
- `determinism.tsv`;
- `scores.tsv`: one row per arm, permutation and item;
- `stats.tsv`: the table in §5;
- `blocks.tsv`.

The B7 run commits these with a `REPORT.md` under `results/<tag>/`.
