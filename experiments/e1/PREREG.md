# E1 pre-registration: which learning mechanisms change what the chat says?

**Status.** This file was registered before any ablation arm was run on
`inputs/replay_v1.tsv`. It is part of the commit that adds the harness (B4).
The study run (B7) uses that commit's inputs and scoring unchanged. Any later
change is listed under "Deviations" in the results' `REPORT.md`.

## 1. Question

The audit (§8, finding F-03) found that most of CrossEngin's learning
mechanisms are called on the chat path but may not change any reply. E1 asks,
for each mechanism:

1. Does switching it off change what the chat says?
2. Does it make the chat more or less correct on a fixed, scored replay?

## 2. Arms

Every arm runs the same chat binary. The arms differ only in environment flags,
which are listed in `arms.tsv` and described in `docs/EXPERIMENT_FLAGS.md`.

The moment cache answers many inputs with another input's reply, which hides
the effect of other mechanisms. Some mechanisms are therefore also tested with
the cache off (the *no-cache context*).

| Arm | Flags | Compared with |
|---|---|---|
| full | none | (reference) |
| abl_substrate | `CE_ABL_SUBSTRATE=1` | full |
| abl_ff | `CE_ABL_FF=1` | full |
| abl_pc | `CE_ABL_PC=1` | full |
| abl_cache | `CE_ABL_CACHE=1` | full |
| abl_ia | `CE_ABL_IA=1` | full |
| abl_synw | `CE_ABL_SYNW=1` | full |
| abl_beta | `CE_ABL_BETA=1` | full |
| abl_all | all seven ablations | full |
| hebb | `CE_HEBB=1` | full |
| hebb_nocache | `CE_HEBB=1 CE_ABL_CACHE=1` | abl_cache |
| nocache_beta | `CE_ABL_CACHE=1 CE_ABL_BETA=1` | abl_cache |
| nocache_synw | `CE_ABL_CACHE=1 CE_ABL_SYNW=1` | abl_cache |
| nocache_ia | `CE_ABL_CACHE=1 CE_ABL_IA=1` | abl_cache |

That gives 13 comparisons.

## 3. Inputs

`inputs/gen_v1.py` generates both `inputs/replay_v1.tsv` and
`inputs/gold_v1.tsv`, and holds every item and gold rule in one place. The
replay has 262 lines: 200 scored items, 25 unscored probe items and 37 feedback
lines. They are grouped into episodes, and the episodes into seven blocks. The
blocks always run in the order R, P, C, U, B, F, H.

| Block | Scored | What it probes |
|---|---|---|
| R: recall | 40 | Seed concepts, asked singly, twice in a row, or as a pair from one moment-cache cluster. |
| P: paraphrase | 30 | Rewordings that should reach the same reasoning chain as a canonical concept. |
| C: category | 40 | Arithmetic, greetings, thanks and farewells, social and personal replies, refusals, self-description, NL-grammar research, procedural, financial, debatable, yes/no. |
| U: unknown | 25 | Nonce words and unknown procedures. |
| B: belief feedback | 16 | 15 hedge episodes and 1 intent-adaptive episode, described below. |
| F: flip feedback | 9 | Flip episodes, described below. |
| H: held-out retest | 40 | Earlier items asked again at the end of the session, after all feedback. |

**R pairs.** The two-item episodes are exercise/diet, diet/vitamin,
vitamin/exercise, question/ask, ask/question, infection/symptom,
symptom/infection, need/hello, wake/morning, happy/sad, sad/happy and
response/answer. Repeats such as virus/virus are also two-item episodes.

**U items.**
- A first sight should give an honest gap that names the word.
- The two words that are each asked twice should get the "say more" reply on
  the second sight.

**B episodes** (before F, so flip feedback cannot reach a hedge operator
before its item is scored).
- **Hedge episodes (15).** A yes/no question is its own probe, so the feedback
  lands on the single operator it asks about. Each episode uses a different
  operator. The question is followed by `/good /good` (one item asks
  `is exercise healthy?` and expects an unhedged chain) or `/bad`, then the
  same question again.
- **Intent-adaptive episode (1).** The debatable question "what should i do
  about my treat" gets one `/good`. Then the plain concept `treat`, asked
  nowhere earlier, must not get a debatable reply.

**F episodes (9 flips).** The probe is followed by `/bad`, `/bad /bad` or
`/correct fever causes pain`, then the same input again.

**H items.** Some check stability; others check whether the learned changes
persist.

**Cache clusters are session-wide.** The moment cache's key is a hash of the
active concepts, and it ignores category. So whichever member of a cluster is
asked first can answer every later member of that cluster, anywhere in the
session. That includes the R, P, F and H items, and nonce words in U, which
can collide with each other. The order of items within a pair therefore does
not isolate the effect. The scored outcome is what each input gets in the
permuted session.

**Permutations.** `inputs/perms_v1.tsv` holds five permutations, generated by
`e1.py perms` with seeds 1–5. Each one shuffles the episodes within every
block; the order of lines inside an episode is fixed. Every arm runs all five
permutations.

**Run conditions.**
- Each (arm, permutation) pair runs in its own chat process, with a fresh
  private run dir (mode 0700).
- The process gets an environment built from scratch: `HOME`, `CE_RUN_DIR`,
  `CE_EXP_TRACE=1`, `CE_CAPS_CONF=inputs/caps_e1.conf` (denies every
  capability that could prompt or reach the network), plus the arm's flags.
- An inert marker line (`/__e1_<id>`) before each item makes the replies line
  up with the items.
- Raw output is kept byte for byte.

## 4. Outcome

**Per-item correctness.** Each item's gold is in `inputs/gold_v1.tsv`. When a
spec has several parts, all of them must hold. The kinds:

| Kind | Correct when |
|---|---|
| `about=W` | The reasoning chain in the reply begins or ends at concept W. |
| `chain=W` | W is a node of the reply's reasoning chain (the reply stays on topic). |
| `ops=CSV` | The EXP trace's operator ids equal CSV. This is the paraphrase check: the same chain as the canonical concept. |
| `line=TEXT` | The `agent>` line equals TEXT. |
| `prefix=TEXT` | The `agent>` line starts with TEXT. |
| `not=TEXT` | The `agent>` line is non-empty and does not start with TEXT. |
| `differs=ID` | The `agent>` line differs from item ID's line in the same run. |
| `nl=1` | The NL grammar answered. |

The flip items and their H retests use `chain=<concept> && differs=<probe>`:
after `/bad` the reply must change *and* keep the concept in its chain. F05
(`/correct fever causes pain`) requires `pain` in the chain.

Limitation: in the infection/symptom/fever cluster, most chains contain all
three concepts. So a cached reply that belongs to a neighbouring concept can
still pass `chain=`. `about=` is not used for these items, because the fresh
reply to `fever` never begins or ends at fever.

**How the gold was written.**
- The semantic kinds were not tuned to the system's output. These are
  `about`, `chain`, `differs`, `not`, `ops` (the canonical concept's chain)
  and the hedge prefixes (`yes [from seed]` after two `/good`,
  `tentatively, yes` after one `/bad`). `healthy` (P16) is the conclusion of
  three seed operators, so it is scored `about=healthy`.
- Exact reply texts (`line=`, and the other `prefix=` values) were transcribed
  from the chat's replies.

**Reference check.** `e1.py refcheck` runs every episode alone in the full arm.
At registration, 26 of 200 scored items fail their gold there:
- cache collisions within a cluster: R04b–R11b;
- a semantic miss: R22 "pain";
- the intent-adaptive override: B16q, and its retest H40;
- replays or off-topic replies after feedback: F01q, F02q, F04q, F05q, F06q,
  F07q, F09q;
- in the file-order run, cache replays and collisions late in the session:
  H03, H04, H06, H07, H36, H37, H39;
- the late arithmetic item H25.

All 15 hedge items pass alone.

**Full arm on all five permutations** (run before registration; the full arm
only). It is byte-identical across reruns, and 164 of 200 items are correct by
majority. Majority-wrong:
- B: B06q, B09q, B10q, B13q, B14q, B16q;
- F: F01q–F09q;
- H: H03, H04, H06, H07, H25, H36, H37, H39, H40;
- P: P21;
- R: R04a, R04b, R05a, R06b, R07b, R08a, R09a, R10b, R11b, R22;
- U: U04.

The five hedge items are wrong because `/good` and `/bad` do not invalidate
the moment cache. When the probe brings in no new word, the follow-up gets the
probe's own cached, pre-feedback reply. B06q, B09q and B14q also repeat a
question asked earlier in C or P.

Before registration:
- two yes/no items were replaced, because the chat cannot parse them in any
  context ("i don't have a model of 'lead'");
- the item set was revised after an adversarial review.

**Arm-level score.** An item counts as correct for an arm if it is correct in at
least 3 of the 5 permutations.

## 5. Analysis

**Primary.** For each of the 13 comparisons, an exact two-sided McNemar test is
run over the 200 items:
- b = items correct in the comparator but not in the arm;
- c = items correct in the arm but not in the comparator;
- p = min(1, 2·Σ_{i≤min(b,c)} C(b+c, i) / 2^(b+c)).

The 13 p-values are Holm-adjusted, and a comparison is significant if its
adjusted p < 0.05.

**Secondary (descriptive, not tested).**
- `items_text_differs`: the number of scored items whose whole reply text (EXP
  lines removed) differs from the comparator's in at least one permutation.
  This measures behavioural change without any judgement of correctness.
- Pooled correctness per block and arm (`blocks.tsv`), over item ×
  permutation.

**Determinism gate.** The full arm is run twice on every permutation. If any
pair differs by a single byte, the study stops before scoring.

## 6. Hypotheses and predictions

A *null prediction* below ("no significant difference") counts as refuted if
the comparison is significant **or** if b + c ≥ 10. Either way, that many
discordant items is a behavioural effect worth reporting.

- **H1: the moment cache costs correctness.** abl_cache is significantly better
  than full (c > b). The predicted gains are on cluster collisions (R, P, H),
  colliding nonce words (U), flip re-asks (F, H), and hedge follow-ups in B
  that the cache answers with the pre-feedback reply (it is not invalidated by
  feedback).
- **H2: three mechanisms change nothing a user can see.** For abl_substrate,
  abl_pc and abl_ff, `items_text_differs` = 0 and b = c = 0. A single
  differing item refutes H2 for that arm.
- **H3: operator confidence (BETA) carries the hedge.**
  - The main test is nocache_beta vs abl_cache: significantly worse (b > c).
    The losses should come from the hedge items B01q–B15q and from H38/H39.
  - abl_beta vs full is predicted to point the same way (b > c), but its
    significance is not predicted, because the cache already makes many hedge
    items wrong in full.
  - Null predictions: abl_synw vs full and nocache_synw vs abl_cache, because
    compiled shortcuts are not expected to win a chain choice.
  - IA: abl_ia and nocache_ia are predicted to gain on B16q, H40 and the late
    arithmetic item H25, where reinforced intent prototypes misclassify
    `15% of 200`. That is at most 3 items, so a null prediction applies.
- **H4: everything off.** No direction is predicted for abl_all vs full. It
  should gain where the cache hurts and lose where BETA helps. The result is
  reported either way.
- **H5: the B3 Hebbian step.** Null predictions for hebb vs full and for
  hebb_nocache vs abl_cache; Hebb changes the chain choice mainly at the fever
  fork.
  - **Decision rule:** `CE_HEBB` becomes on by default only if **all** of
    these hold:
    1. hebb_nocache vs abl_cache is significant with c > b;
    2. hebb vs full (the shipped configuration, cache on) shows no
       significant difference with b > c;
    3. no block's pooled correctness is lower in hebb than in full, or in
       hebb_nocache than in abl_cache.

## 7. Known threats

- Items within one session are not independent: feedback in one episode can
  move operators that a later item uses, and the moment cache links inputs
  across the whole session. Permuting episodes and taking a majority over five
  permutations spreads these effects evenly across arms. It does not remove
  them.
- The gold encodes judgements: a reply about a different concept is wrong, a
  reply should change and stay on topic after `/bad`, and the hedge should
  follow the feedback. Other judgements would score differently.
  `items_text_differs` is reported for that reason.
- The seed knowledge is small (42 operators). Results describe this seed only.
- Disclosure: exploratory runs on ad-hoc scripts, which were not this replay,
  informed the item design. These are the cache collisions, the BETA/SYNW
  masking, and the observation that SUBSTRATE, PC and FF never changed a reply
  in those runs.
  - An adversarial review used ablation arms only on its own synthetic
    sessions. That is how it found that IA changes late arithmetic.
  - Before registration, only the full arm ran on `replay_v1.tsv` (§4).

## 8. Outputs

`e1.py run` writes the following to its output directory:
- `manifest.json`: SHA-256 of the binary and of every input file, the git
  revision and dirty flag, and the Python version;
- `raw/<arm>/p<k>.out`: the exact bytes;
- `determinism.tsv`;
- `scores.tsv`: one row per arm, permutation and item;
- `stats.tsv`: the table in §5;
- `blocks.tsv`.

`e1.py stats` refuses to re-score if any input differs from the manifest. The
B7 run commits these with a `REPORT.md` under `results/<tag>/`.
