# ADR-0039: Theory of mind in concept layer (user-as-concept with rich properties, updates from observation, used for empathy and anticipation)

## Status

Proposed

## Date

2026-05-25

## Context
A companion that cannot model the person it serves is a tool, not a companion. CrossEngin's target capabilities explicitly include theory of mind: representing the user's knowledge, preferences, goals, emotional state, and habits, updating that model from observation, and using it for empathy (responding to how the user actually feels) and anticipation (acting before being asked). This is one of the 8 capability tests (ADR-0049). On the desktop deployment (ADR-0046) there is exactly one user to model deeply over months; in the enterprise pilot (ADR-0047) the modeled party may be a specific employee, one per tenant process.

The question is *where* this model lives. CrossEngin already has a concept layer (`core/concept.nova`, ADR-0018) with hierarchy, schemas, and multi-vector embeddings, and a multi-KG store (ADR-0017) where atoms carry Bayesian confidence (ADR-0016, ADR-0023) and cross-KG references (enhancement #8). The user is not a separate subsystem — they are a *concept the system holds*, exactly the kind of rich, evolving, multi-faceted entity the concept layer was built for. Treating the user as a first-class concept (rather than a flat profile table) lets the model participate in normal substrate dynamics: spreading activation, prediction (ADR-0024), emotion appraisal (ADR-0035), and reasoning (ADR-0031).

This must be decided now because empathy and anticipation touch emotion (ADR-0035), goals (ADR-0033), and the self-model API (ADR-0038) being defined alongside it, and because privacy/safety (ADR-0045) constraints on storing a model of a person must be designed in, not bolted on. Constraint: 2 founders, NOVA (ADR-0005), no LLM (ADR-0014) — the user model is learned from observed moments, not prompted out of a language model.

## Decision
We represent the user as a **first-class `user-as-concept` in `core/concept.nova`**, a rich concept node with multi-vector embeddings and a schema of property atoms, backed by a dedicated KG (e.g. `KG-user`) via the multi-KG mechanism (ADR-0017, enhancement #8). It is not a flat profile; it is a concept that participates fully in substrate dynamics.

The concept carries property atoms (ADR-0016), each Bayesian-confidence-weighted (ADR-0023): stable traits (preferences, communication style, domain expertise, relationships), slow-changing context (current projects, recurring routines), and fast-changing state (inferred mood, energy, attention). Properties are **updated from observation**: every user-originated moment (ADR-0021) is appraised and, where it carries evidence about the user, updates the relevant property's alpha/beta counts — co-occurrence strengthening via Hebbian synapses (ADR-0007), and prediction mismatches (the user did something the model didn't expect) driving error-based revision (ADR-0024). Cross-KG references (enhancement #8) link `user-as-concept` properties to domain atoms — e.g. the user's medication concept references `KG-medicine` atoms — so the model is grounded, not isolated.

The model is *used* two ways. **Empathy:** the user's inferred affective state feeds the emotion system's OCC appraisal (ADR-0035), conditioning the system's own valence/arousal and shaping output tone (ADR-0013) — a frustrated user yields gentler, briefer responses. **Anticipation:** the goal engine (ADR-0033) reads predicted user needs from the model to spawn proactive sub-goals (e.g. surface a reminder before the user asks), generating initiative — itself a capability test (ADR-0049). Predictions about the user are imagined forward (ADR-0032) before action, and all proactive actions pass permission tiers (ADR-0041) and reversibility (ADR-0042).

## Options Considered
**Flat user-profile record (key/value store outside the substrate).** Simple, inspectable, easy to edit and to delete for privacy. Rejected as primary because a flat record cannot do spreading activation, cannot carry graded confidence naturally, cannot link to domain knowledge via cross-KG refs, and cannot participate in prediction/appraisal — it would sit outside the dynamics and require special-case orchestration, violating the substrate thesis (ADR-0001). A flat *export view* of the concept is still useful for user inspection/deletion (ADR-0044) and we keep that as a projection, not the store.

**Dedicated theory-of-mind module separate from the concept layer.** Clean separation of concerns; could be optimized independently. Rejected because it duplicates exactly what `core/concept.nova` (ADR-0018) already provides (hierarchy, schemas, multi-vector embeddings) and would need its own update, decay, and reference machinery — wasteful for 2 founders and architecturally redundant. Theory of mind *is* concept modeling applied to a person.

**User-as-concept in the concept layer with a backing KG (CHOSEN).** Reuses the concept layer, multi-KG (ADR-0017), Bayesian confidence (ADR-0023), and predictive coding (ADR-0024) wholesale; integrates natively with emotion (ADR-0035) and goals (ADR-0033) for empathy and anticipation; grounded via cross-KG refs (enhancement #8). Costs: a person modeled in mutable substrate raises real privacy obligations and the risk of confidently-wrong inferences. Accepted with explicit safety gating (ADR-0045) and confidence-aware use.

## Consequences
- **Positive:** Theory-of-mind capability satisfied as an emergent substrate property, not a bolt-on (ADR-0049); native empathy via emotion coupling (ADR-0035) and initiative via goal coupling (ADR-0033); grounded, confidence-weighted, continuously-updated user model that improves over months of companionship; cross-domain grounding through enhancement #8.
- **Negative:** Storing a rich evolving model of a real person is a significant privacy and safety surface — it must be user-inspectable and user-deletable (ADR-0044) and constitution-gated (ADR-0045), and in v2 must never leak across tenants (ADR-0047). Confidently-wrong inferences can produce creepy or misjudged anticipation; we mitigate by gating proactive action on confidence thresholds (ADR-0023) and permission tiers (ADR-0041). Coupling into emotion and goals widens the blast radius of a bad user-model update.
- **Future work:** Multiple user concepts and modeling third parties the user talks about (relationship graph); explicit "I might be wrong about you" disclosure via the self-model API (ADR-0038); decay tuning so stale mood inferences don't persist; consent/onboarding flow for what may be modeled.

## Implementation Notes
Create `user-as-concept` via `concept_new` in `core/concept.nova` with a property schema; back it with a `KG-user` spawned through the ADR-0017 mechanism. Property atoms via `atom_new` carrying alpha/beta (`core/belief.nova`, ADR-0023); cross-KG links via `core/similarity.nova` weighting (enhancement #8). Observation updates run in the memory + emotion loops (ADR-0036): a `user_observe(moment)` routine appraises user-originated moments (ADR-0021) and updates properties (Hebbian via ADR-0007, error via ADR-0024). Empathy hook: feed inferred user affect into `mind/emotion.nova` OCC appraisal (ADR-0035). Anticipation hook: `goal_spawn_proactive(predicted_need)` in `core/goal.nova` (ADR-0033), with forward simulation via `core/imagination.nova` (ADR-0032) and a mandatory pass through `core/safety.nova` permission tiers (ADR-0041) and reversibility (ADR-0042). Provide a flat projection `usermodel_export()` for inspection/deletion (ADR-0044). Testing: feed a scripted multi-day moment stream, assert a preference property's confidence rises and a wrong prediction triggers downward revision; assert a high-confidence predicted need spawns a proactive (but permission-gated) goal; a privacy test asserting export+delete clears the concept and its KG atoms; v2 tenant-isolation test (ADR-0047). Depends on ADR-0016/017/018/023/024 (representation), ADR-0032/033/035 (use), ADR-0041/044/045 (safety). Leans on enhancement #8 (multi-KG cross-refs). No LLM anywhere (ADR-0014).
