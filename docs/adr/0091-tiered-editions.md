# ADR-0091: Tiered editions — Edge / Enterprise / Research

## Status

Proposed

## Date

2026-06-15

## Context
The roadmap (ADR-0086) reaches a point — Phase 6 — where the same cognitive core has to ship into very different environments. A robot, a phone, or an OS-embedded assistant cannot run the same configuration as a multi-tenant cloud deployment, and neither of those should expose the raw introspection surfaces the team and research partners need. We have one substrate (ADR-0001) and one debate engine (ADR-0089); the question this decision settles is how many *products* we cut from them and how. We must decide now because edition boundaries propagate backward into things being built today: which KG partitions a build is allowed to load (ADR-0087 clean vs. quarantine), how many active parts a process budgets (ADR-0003), and whether the autonomous self-update loop (ADR-0092) is even present.

The forces pull in opposite directions. Edge targets are hardware-constrained and often offline: a vehicle or an embedded assistant has a fixed RAM and power envelope and may have no network, so it needs a small, frozen, self-contained brain that does no outbound research. Enterprise targets are the opposite: full reasoning, multiple paying tenants, hard isolation, audit, and eventually horizontal scale. Research is a third axis entirely — not constrained and not multi-tenant, but maximally *transparent*, exposing the internals (argument graph, decision log, belief state) that the other two editions deliberately hide. One configuration cannot satisfy all three.

The binding constraint is that a two-founder bootstrap team cannot maintain three codebases. Divergence would be fatal: every reasoning fix would have to land three times, and the editions would drift until "the same engine" was a marketing claim rather than a fact. So whatever we ship, the editions must be the *same core* configured differently — selected by a manifest, by which KG partitions and snapshots load, and by which loops run — not three forks. There is also a commercial-cleanliness constraint (Rule 3): an Edge build that ships to a customer device must provably contain no quarantined (unlicensed / non-commercial) atoms (ADR-0087), because we cannot audit what is running on hardware we do not control.

One honesty note up front: producing the Edge edition is not just a packaging exercise. Distilling and pruning a 1M+ node substrate (ADR-0003) down to something that fits constrained hardware is real, unsolved research, and the substrate fundamentally needs threads and a running tick (~100Hz) — per the embedding analysis there is no browser/single-threaded-runtime target. Edge means "small native process," not "runs anywhere."

## Decision
Ship **one shared cognitive core** (ADR-0001 substrate + ADR-0089 debate engine + the belief/provenance machinery) as **three editions** selected by an edition build manifest. The editions differ only in configuration — which KG partitions/snapshots load, which loops run, and which introspection surfaces are exposed — never in core source. This is ADR-0086 Phase 6.

- **EDGE** — distilled, offline-capable, runs on constrained hardware (robots, phones, OS-embedded assistants, vehicles). Ships a frozen, curated, **commercially-clean** trusted-KB snapshot that **excludes the ADR-0087 QUARANTINE partition** entirely. Reasoning is bounded: the ADR-0089 argument graph is size-capped, and the process budgets fewer/smaller active parts within the ADR-0003 envelope. Autonomous outbound research (ADR-0092) is gated or fully off. Single-process, no consensus, no multi-tenancy. Still requires the substrate's threads + tick — Edge is a small native process, not a browser target.

- **ENTERPRISE / CLOUD** — full reasoning, multi-tenant via the ADR-0047 model (one tenant per process, read-only base-brain snapshot + writable tenant overlay, strong isolation, constitution seeded per tenant). Scales out to distributed operation using NOVA-0007 (storage engine) and NOVA-0008 (Raft consensus), with KGs sharded per ADR-0003 as we cross the 1M→1B node re-architecture. Constitution enforced and non-revisable (ADR-0045); per-tenant isolation and full audit (ADR-0043).

- **RESEARCH** — full introspection for the team and research partners. Exposes the ADR-0089 argument graph, the decision log (ADR-0043), and belief internals (ADR-0023), and provides an experiment harness for benchmarking against LLMs (ADR-0093 Phase 7). No distillation, no hidden surfaces, not multi-tenant.

All three are the **same binary/core** configured by the edition manifest plus which partitions/snapshots load and which loops run. This is explicitly NOT three codebases.

## Options Considered
- **One core + edition manifest (CHOSEN).** A single substrate/debate-engine codebase, with editions expressed as a manifest selecting KG partitions, active-part budget, loop set, and introspection surfaces. Cost: the manifest and the build/packaging tooling are net-new, and the Edge distillation problem is real research that this decision does not solve (it only gives it a home). Chosen because it is the only option a two-founder team can maintain without the editions silently diverging.
- **Single one-size edition (rejected).** Simplest to build and ship. Rejected on both ends: constrained edge hardware cannot run the full 1M+ node substrate (ADR-0003), and the multi-tenant isolation Enterprise requires (ADR-0047) is exactly what a transparent Research build must NOT have. No single configuration is simultaneously small enough, isolated enough, and open enough.
- **Three separate codebases (rejected).** Lets each edition optimize freely. Rejected: triples the maintenance surface for every reasoning change, and the forks would diverge until shared correctness guarantees no longer held. Unaffordable and dangerous for a small team — the editions would stop being the same engine.

## Consequences
- **Positive:** One reasoning core to fix, test, and certify; every improvement lands once and reaches all editions. Commercial cleanliness for Edge is provable by construction (the manifest excludes the ADR-0087 quarantine partition, so a clean build *cannot* contain quarantined atoms). Enterprise reuses the already-designed ADR-0047 isolation model rather than inventing new multi-tenancy. Research gets full transparency without a separate engine.
- **Negative:** Edge distillation/pruning of a 1M+ node substrate to fit constrained hardware is unsolved research and the largest risk in this ADR; this decision scopes it but does not de-risk it. The manifest becomes a security-relevant artifact — a misconfigured Edge manifest could ship quarantine atoms or leave outbound research on, so it needs its own verification. Enterprise scale-out drags in the ADR-0003 1M→1B discontinuity (sharding, multi-process via NOVA-0007/0008), which is itself a hard, separate re-architecture. Maintaining one core across three very different deployment shapes adds configuration complexity even though it removes codebase duplication.
- **Future work:** The actual distillation method for Edge (which atoms/parts to keep, how to cap the argument graph without crippling reasoning quality). Intermediate editions or per-customer Edge profiles once the distillation pipeline exists. Tighter coupling between the manifest and the ADR-0092 self-update governance so an edition's update posture is part of its identity. Benchmark suite (Research, ADR-0093 Phase 7) maturing into a published comparison vs. LLMs.

## Implementation Notes
Define an **edition build manifest** that selects: (1) which KG partitions load — clean trusted-KB vs. ADR-0087 quarantine (Edge: clean only); (2) the active-parts / RAM budget per the ADR-0003 envelope (Edge: fewer/smaller parts; per-part ~12GB and "few active parts per process" still apply); (3) the loop set — notably whether the ADR-0092 autonomous outbound-research loop runs (Edge: gated/off); (4) the introspection surfaces exposed (Research: argument graph + decision log + belief internals + experiment harness; Edge/Enterprise: hidden). The argument-graph size cap is an ADR-0089 parameter set by the manifest. For Enterprise, reuse the ADR-0047 host supervisor verbatim for one-tenant-per-process placement, base-brain/overlay snapshot split, and per-tenant constitution seeding (ADR-0045) — Enterprise adds scale (sharded KGs, NOVA-0007 storage, NOVA-0008 consensus), not a new isolation model. The manifest itself is security-relevant and must be verified at build time, especially the clean-vs-quarantine partition selection.

Testing: an Edge build provably contains zero atoms from the ADR-0087 quarantine partition AND performs no outbound fetch (the ADR-0092 loop is absent/disabled); an Enterprise build isolates two tenants with no cross-tenant leakage (reuse the ADR-0047 isolation test verbatim — teach tenant A a private fact, verify tenant B cannot retrieve or be influenced by it); a Research build can render a complete argument trace (ADR-0089) and decision log (ADR-0043) for a given query.

DEPENDS ON: NOVA-0007 (Enterprise/scale persistence — replaces today's text-file gap), NOVA-0008 (distributed Enterprise consensus), NOVA enhancement #1 (pre-allocated node arenas, per-process budget), NOVA enhancement #10 (snapshots). Builds on: ADR-0001 (shared substrate core), ADR-0089 (shared debate engine + graph cap), ADR-0087 (clean vs. quarantine partition selection), ADR-0047 (Enterprise multi-tenant model reused), ADR-0003 (active-parts budget + 1M→1B scaling), ADR-0045 (constitution enforcement), ADR-0043 (audit / introspection), ADR-0092 (Edge research-loop gating), ADR-0093 (Research benchmark harness, Phase 7), ADR-0086 (Phase 6 mandate).
